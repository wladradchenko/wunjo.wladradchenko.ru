# Working from a reference

"Like this video" is the most useful brief a user can give and the easiest to
misread. Extract the mechanics, not the surface.

## Describe it in measurements

Watch or analyse the reference and write down what is actually happening:

- **Pacing** — average shot length, and where it deliberately slows.
- **Structure** — how long before the first payoff, how sections are signposted.
- **Frame language** — shot sizes used, how much movement, how busy the frame is.
- **Type** — how much on-screen text, where it sits, how long it holds.
- **Sound** — music presence under speech, effects, use of silence.
- **Colour** — warmth, contrast, saturation, and whether shots match.

If the reference is in the project, `describe_media`, `detect_scenes` and
`render_contact_sheet` give you shot lengths and the visual grammar directly.
`transcribe_media` gives the script structure and how quickly it gets to the
point.

## Separate what transfers from what does not

State plainly which parts the user's material can support. A reference shot on
location with three cameras does not transfer to one screen recording — but its
pacing, its structure and its restraint do. Say which is which before starting,
so the user is not expecting the impossible.

## Do not clone

Copy the mechanics, not the identity. Reusing a reference's exact type, colour
signature, music and opening line produces something that reads as an imitation
of a specific channel — which is both worse work and someone else's brand.

Take the decision, then make it yours: "shots average 2 s and the type is always
bottom-left" is a mechanic worth keeping; "the same font and the same intro
sting" is not.

## Turn it into a read

Finish by writing the taste-direction read and the three dials from what you
measured, put them in the chat, and get agreement. From then on the reference
has done its job — work from the read, not by re-watching.

See also: taste-direction, brief-intake.
